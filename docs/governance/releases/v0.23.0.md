# 0.23.0 verification record

Every pull request merged since v0.22.0 is traced to the CHANGELOG entry that describes it, every entry's claims are checked against the code at the release commit, and every issue those pull requests closed is checked against what it asked for. Corrections land in `CHANGELOG.md` in the same change as this record, before the release. [`RELEASE.md`](../RELEASE.md) makes this record part of every release.

- **Range:** `v0.22.0` (`af52863`) to `main` at `0b5fd4a`.
- **Checked against:** `main` at `0b5fd4a`. The release pull request (#556) adds the version, the release heading and two Breaking notes (below). What else it ships is the outcome of the re-reads in checklist step 8: the `ec-battery-guidance` and `idta` records in `dpp-vocab`, and a doc comment in `passport_content.rs` saying the guidance's version 3.2 changes no obligation and no disclosure class.
- **Date:** 2026-11-03.

## How each claim was checked

A claim is **verified** when the code at the release commit does what it says. Evidence is one of:

- the source location that implements it;
- a test that pins it, by name (every test named below is in a suite that passed on 2026-11-03: `just check`, and the JSON-LD oracle on `0b5fd4a`);
- a measurement, where the claim is a number.

Every backticked path and identifier in the section was also checked mechanically to exist outside the CHANGELOG. Ten did not, and all ten are legitimate: three names the entries describe as removed, a message template, four JSON paths, a JSON-LD IRI built at run time, and a file named by a partial path (`jsonld/envelope_terms.rs`), which exists.
